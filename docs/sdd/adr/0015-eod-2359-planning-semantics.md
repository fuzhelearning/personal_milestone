# ADR-0015: 日终 23:59 合一；planning 语义；备注必重排；改期只动日安排

- Status: Accepted
- Date: 2026-08-02
- Deciders: 用户
- Related: ADR-0002/0003/0008/0014；02/03/07/08

## Decision

### 1. 日终只用 **每天 23:59**（合并原 23:30 回写 + 顺延/周日重排）

对每个用户时区「当地 23:59」跑一次 `day_close`（可内部分步）：

1. 当日仍 `pending`（未勾选、未提交未完成）→ `not_done`（原因可默认「超时未反馈」）  
2. 回写 Structure `progress_pct`（原 23:30 逻辑并入）  
3. **分支**：  
   - **非周日**：未完成项 **顺延到下一天**（新增一条 `day_assignments`，`source=defer`）。若明天**已有**别的任务：**直接叠加上去**，**不改动、不挤掉**原有任务（同一 Goal 同一天可有多条安排）  
   - **周日**：不走「简单挪到周一」为主路径，而是 **生成新计划**（重排后续日 `day_assignments`，AI + 规则兜底；等同原 sunday_replan）

> 不再单独依赖「每天 23:30」作为 P0；催办（21:00）仍可选 P1。  
> 用户主动提交未完成：仍可立即顺延到下一天（不必等 23:59）。

### 2. 只改备注也要重排

- `plan-edit` 仅改 `note`、完成日不变 → **仍立刻入队** AI 重排未来 `day_assignments`（备注进 prompt）。  
- 首期 **不改** milestone/task 节点起止（与 §5 一致）。

### 3. `planning` 语义

- **不是**「还没生成任务」。  
- **是**：已有排期/任务，只是（部分）任务日期未到，或目标处于「计划中」展示态。  
- 首页 `today_tasks` / `rest_of_week`：**包含** `planning` 与 `active`（只要当天/本周有 assignment）。  
- 「生成中 / 待确认」请用 `draft`（或实现时加 `generating`），勿再占用 `planning` 表示「无任务」。

### 4. 改完成日面板默认最早可选日

- 打开编辑时日期默认 = `max(current+1, today+3)`。  
- **没有**产品上的「延误」污名概念；此默认只为满足 ADR-0002 下限，不是标记用户延期。

### 5. 完成日/备注触发的重排：只改日安排

- 确认：只动 **明天及以后** 的 `day_assignments`。  
- **不改** 已确认 WBS 里程碑/任务的结构与起止日（首期）。  
- 今日 assignments 不变（ADR-0002）。

## Supersedes / 清理

- 日终主时钟：23:59（非 23:30）  
- 废止「一天塞 5 条」装箱假设  
- **AI 初排**仍建议一目标一天一事；**顺延叠加**允许同日多条（见上）  
- ADR-0003「先催办再未完成」不作为 P0；P0 = 23:59 自动结算  

### 顺延叠加（用户 2026-08-02 确认）

- 明天已有任务 A，今日未完成 B → 明天 = A + B  
- 首页「今日任务」同一 Goal 允许多条  
- DB：保留 `UNIQUE(goal_id, task_id, plan_date)`；**删除** `UNIQUE(goal_id, plan_date)`  
- 同日多条的「结清 / 进度条延期色」见 **[ADR-0016](./0016-same-day-multi-task-all-done.md)**
