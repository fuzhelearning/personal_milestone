## 1. 项目定位

本项目是**个人里程碑管理系统的后端**：接收用户目标与截止时间，借助 LLM（DeepSeek）生成可执行的 WBS，沉淀执行反馈，并通过定时任务动态调整后续日计划。客户端为微信小程序。

## 2. 不可协商原则（Constitution）

1. **Spec First**：无 Frozen Spec 不写实现；实现必须可追溯到需求编号（如 `REQ-F-003`）。
2. **按触发源的人在回路（ADR-0001）**：
   - **首次 WBS 生成**：须用户确认后生效。
   - **调整计划完成时间**：须用户调用确认接口后，才重排 **尚未发生** 的 WBS，并同步变更日计划（不含今日）。计划开始后：只能**往后**改完成日（不能往回），且不得早于 **今天+3**（ADR-0002）。
   - **提交执行反馈（未完成/少完成等）**：提交即驱动 **日计划** 调整；**不改变 WBS 总体排期**；日计划不再单独确认。
3. **可解释**：每次 AI 拆分/重排必须留存 prompt 摘要、模型、输入上下文哈希、输出原文与结构化结果，便于审计与复盘。
4. **幂等与可重放**：定时任务、外部 API 调用必须可安全重试；同一业务键不得产生重复副作用。
5. **数据主权**：用户计划与执行日志属于用户私有数据；默认不用于模型训练；日志脱敏。
6. **失败可降级**：DeepSeek 不可用时，系统仍可查看已有计划、提交执行反馈；AI 能力标记为降级，不阻塞核心记录。
7. **小步交付**：先打通「目标 → 两层 WBS → 周计划 → 日报/催办 → 周内顺延 → 周日重排」闭环，再扩展协作、多目标冲突优化等（ADR-0003）。

## 4. 质量门槛（Definition of Done 基线）

- 每个 Frozen 的 `REQ-*` 有对应验收条目（见 `09-acceptance.md`）
- 对外 API 有契约（见 `05-api-contract.md`）且与 OpenAPI 一致
- 写路径有事务边界说明；定时任务有失败重试与死信策略
- AI 调用有超时、重试上限、费用/token 预算字段（即便先不做强控）

## 5. 明确不做（初版 Out of Scope）

- 多目标同日工时抢占 / 配额（ADR-0006）
- AI 自动或建议「砍 scope」（ADR-0006）
- 导入 / 导出（Excel、日历订阅等）（ADR-0006）
- Redis、微信订阅消息（ADR-0005）
- 多人协作、语音输入、多模型路由等（仍可后续扩展）

## 6. 变更流程

Constitution 变更需要：

1. 书面说明动机与影响面
2. 同步修改下游 Spec
3. 记录 ADR
